NASKAH
=====================================================================

[0:00–0:20] PEMBUKA

"Selamat pagi/siang, Bapak/Ibu dan teman-teman. Saya [Nama]. Hari ini
saya akan mempresentasikan aplikasi chat real-time bernama RuangObrol.

Aplikasi ini dibuat untuk menerapkan komunikasi socket antara client
dan server. Fokusnya bukan hanya tampilan chat, tetapi bagaimana pesan
dapat berpindah dari satu browser ke browser lain secara langsung."


[0:20–1:10] KONSEP SOCKET — BAGIAN PENILAIAN 20%

"Sebelum masuk ke aplikasi, saya jelaskan dulu konsep socket yang
menjadi dasar proyek ini.

Socket adalah endpoint komunikasi antara dua proses di jaringan. Pada
proyek ini, satu socket di server terhubung dengan satu socket di
browser. Bedanya dengan HTTP biasa: HTTP membuat koneksi untuk satu
request, lalu koneksi itu selesai. WebSocket mempertahankan koneksi
tersebut, sehingga client dan server bisa saling mengirim data kapan
saja. Jadi bukan hanya client yang bertanya, server juga bisa langsung
mendorong pesan ke client.

WebSocket berjalan di atas TCP. Saya memilih TCP karena chat membutuhkan
data yang lengkap, berurutan, dan tidak hilang. UDP tidak menjamin hal
itu. Prosesnya dimulai dari handshake HTTP dengan header Upgrade:
websocket, kemudian koneksi berubah menjadi kanal dua arah penuh atau
full-duplex.

Di server, setiap client memiliki objek socket dengan socket.id.
Socket.IO adalah library di atas WebSocket yang membantu mengelola
event. Room bukan koneksi baru, tetapi pengelompokan logis di server.
Saat client bergabung, server memanggil socket.join(roomId). Saat
mengirim pesan, server memakai io.to(roomId).emit, sehingga pesan hanya
dikirim ke socket yang berada di room tersebut. Ketika client terputus,
server menghapus socket itu dan memberi tahu anggota room lainnya."


[1:10–1:40] ARSITEKTUR

"Arsitekturnya terdiri dari dua sisi.

Di sisi client ada HTML, CSS, dan JavaScript yang berjalan di browser.
Di sisi server ada Node.js, Express, dan Socket.IO. Express menyajikan
antarmuka web, sedangkan Socket.IO menangani komunikasi real-time.

Server menyimpan daftar pengguna, daftar ruang, riwayat pesan sementara,
dan status mengetik di memori. Tersedia tiga ruang: Ruang Umum,
Teknologi, dan Kampus."


[1:40–2:05] ALUR KOMUNIKASI

"Saat halaman dibuka, client melakukan handshake WebSocket. Setelah
terhubung, client mengirim event session:join berisi nama dan ruang.

Server memvalidasi data, lalu memanggil socket.join(roomId). Server
mengirim balik acknowledgment berisi data pengguna dan riwayat ruang.

Ketika client mengirim chat:message, server menyimpan pesan lalu
menyiarkannya dengan:

    io.to(user.roomId).emit('chat:message', message);

Artinya, hanya client di ruang yang sama yang menerima pesan. Ada juga
presence:update untuk daftar online dan typing:update untuk indikator
mengetik."

=====================================================================
RANGKUMAN SOCKET YANG WAJIB DISEBUT
=====================================================================

Jika waktu presentasi dipotong, pastikan poin-poin ini tetap masuk:

1. Socket = endpoint komunikasi dua proses di jaringan.
2. WebSocket = koneksi dua arah penuh yang tetap terbuka, berjalan di
   atas TCP.
3. TCP dipilih karena pesan chat harus lengkap, berurutan, dan tidak
   hilang; UDP tidak menjamin itu.
4. Handshake dimulai dari HTTP, lalu di-upgrade menjadi WebSocket.
5. Setiap client memiliki socket dengan socket.id di server.
6. socket.join(roomId) memasukkan socket ke room.
7. io.to(roomId).emit(...) mengirim pesan hanya ke socket di room itu.
8. Room adalah pengelompokan logis, bukan koneksi socket baru.
9. Saat disconnect, server membersihkan socket dan memperbarui
   presence.
10. Socket.IO adalah library di atas WebSocket, bukan pengganti
    protokol WebSocket.

=====================================================================
PERTANYAAN YANG MUNGKIN MUNCUL
=====================================================================

T: Kenapa memakai WebSocket, bukan HTTP biasa?
J: HTTP berorientasi request-response. Untuk chat, client harus terus
   bertanya. WebSocket menjaga koneksi tetap terbuka sehingga server
   dapat mendorong pesan secara langsung.

T: TCP atau UDP?
J: WebSocket berjalan di atas TCP. Chat membutuhkan pesan yang lengkap
   dan berurutan, sehingga TCP lebih tepat daripada UDP.

T: Kenapa memakai Socket.IO, bukan WebSocket murni?
J: Socket.IO menyediakan room, acknowledgment, reconnection, dan API
   event di atas transport WebSocket. Pada proyek ini koneksi client
   tetap dibatasi ke WebSocket.

T: Bagaimana pesan tidak bocor ke ruang lain?
J: Server hanya menyiarkan pesan ke room terkait menggunakan
   io.to(roomId).emit(...).

T: Bagaimana mencegah XSS?
J: Server memvalidasi dan membersihkan input, lalu client merender
   pesan memakai textContent, bukan innerHTML.

T: Apa keterbatasan aplikasi?
J: Riwayat masih di memori dan hilang saat server restart. Belum ada
   autentikasi dan database. Untuk produksi perlu HTTPS/WSS.
